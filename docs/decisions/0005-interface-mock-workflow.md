# ADR-0005：固定响应工作台复用既有治理链路

状态：已实现；2026-10-08。

## 背景

用户配置固定响应需要跨 Provider、API、Contract、Scenario、Approval、Release 页面，并手工传递版本 ID。Release 是应用的全量场景集合，手工选择还可能遗漏其他已生效响应。

## 决策

- 增加 Web「接口 Mock」作为默认入口，就地创建服务商和接口，从示例生成待确认的契约格式；响应使用条件表单与直接 JSON 编辑。
- 复用既有服务端管理 API，不新增权威数据副本、状态机或后端权限通道。每一步仍由原领域服务校验、事务提交和审计。
- 保存响应自动校验；「提交发布」提交既有审批请求。审批人与修改人分离规则不变。审批与实际发布权限分别判断，当前本地审批人批准后仍由管理员发布。
- 发布以当前应用和环境的 Active Release 为基线，仅按 Scenario ID 替换本次明确选择的版本，保留所有未选场景。后端仍校验完整集合，包括同接口契约一致性及规则冲突。
- 确认后重新读取权威基线；变化则要求用户重新核对。激活使用原 expectedActivationVersion 的原子并发保护，不能为了重试自动升级预期版本。
- 激活重试使用固定 X-Request-Id，复用后端持久幂等语义；请求响应丢失时可拿回同一 Activation。创建版本根据服务端已有内容恢复；已明确 FAILED 的 Release 在下一次用户重试时换新编码，不复用失败对象。
- 编辑时绑定打开时的应用、环境和接口；切换范围后拒绝保存。跨应用/租户限制、动态模板、Flow、回调或不支持的规则继续使用高级编辑，不能经简单表单静默丢弃字段。
- 页面自动查询发布状态，仅在服务端 APPLIED 时显示已生效。读取失败或节点失败明确显示未确认，不伪造成功，不自动回退真实第三方。

## 兼容与边界

既有管理 API、数据库、签名快照和历史页面不变。复杂编辑和回滚保留在高级入口；本次不开放本地免审批，不实现 Callback/Flow 发布，也不自动注册 App/Token。JSON 示例推导类型而非必填或常量约束，用户需在创建时确认 Schema。

工作台没有跨多个管理 API 的大事务；成功步骤持久保留，失败可以重试，关闭页面后也能从原高级页面查找已创建资源。尚未保存的表单不作持久草稿。页面关闭不会取消服务端已提交的审批或发布。

## 验证

Web 单元与 API 编排测试覆盖集合合并、复杂场景编辑保护、丢失响应后的版本恢复、契约续接、无效响应不提交审批、当前身份透传、激活幂等请求 ID，以及基线变化拒绝。真实 MySQL/Redis 与浏览器验收独立于离线测试，不以 HTTP 测试替身替代真实基础设施结论。
