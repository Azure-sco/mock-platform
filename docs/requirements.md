# 巡天第三方接口 Mock 平台需求规格说明书

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档名称 | 巡天第三方接口 Mock 平台需求规格说明书 |
| 版本 | v1.0 |
| 适用范围 | OA、e 签宝、共享平台等第三方 HTTP 接口 |
| 目标用户 | 后端开发、测试、联调人员、平台管理员 |

## 2. 背景与问题

巡天多个业务服务依赖 OA、e 签宝、共享平台等外部接口。当前测试依赖第三方环境和协作人员，导致环境不可控、异常分支覆盖不足、异步回调难以复现、临时 Mock 分散且不可审计。

## 3. 产品目标

1. 业务服务引入 SDK 后，通过一个注解和配置开关即可切换真实调用与 Mock 调用。
2. Mock 平台独立部署，不将场景逻辑和测试数据写入业务服务。
3. 支持成功、失败、驳回、处理中、超时、重复回调、回调失败等场景。
4. 支持按环境、应用、接口、租户、测试账号进行隔离和灰度。
5. 提供契约管理、场景编排、状态机、回调、调用记录、回放、审计和回滚。
6. 使用 AI Agent 辅助契约解析、场景生成、测试编排和问题分析，但不参与实时 Mock 响应决策。

## 4. 用户角色

| 角色 | 主要任务 |
|---|---|
| 开发人员 | 引入 SDK、增加注解、调试接口、查看调用记录 |
| 测试人员 | 选择场景、执行流程、推进状态、回放请求、查看报告 |
| 平台管理员 | 管理服务、接口、权限、发布、回滚和审计 |
| 评审人员 | 审核 AI 生成场景和高风险配置 |

## 5. 功能需求

### 5.1 SDK 接入

**优先级：P0**

- 提供 Spring Boot Starter。
- 支持 `@ThirdPartyMock(provider, api)` 注解。
- 支持 Feign、RestTemplate、WebClient；Forest 通过独立适配器接入。
- 支持 REAL、MOCK、CANARY 三种运行模式。
- 支持 Nacos/Apollo 动态刷新配置，无需重启。
- 支持 TraceId、MockRequestId、ScenarioId 透传。
- 支持 Mock 服务不可用时的明确失败策略：快速失败、回退真实、返回兜底响应。
- SDK 不保存场景规则和流程状态，只负责拦截、路由、协议适配和指标埋点。

### 5.2 第三方服务与接口管理

**优先级：P0**

- 注册第三方服务、真实地址、认证方式、负责人和所属环境。
- 管理接口方法、路径、请求参数、响应 Schema、错误码和签名规则。
- 支持 OpenAPI/JSON Schema 导入。
- 支持契约版本、草稿、发布、回滚和变更 diff。

### 5.3 场景管理

**优先级：P0**

- 支持固定响应和模板响应。
- 支持按 Header、Query、JSONPath、正则、业务单号匹配。
- 支持场景优先级、有效期、应用范围、租户范围和测试账号范围。
- 内置 OA 审核通过/驳回、e 签宝签约成功/失败、共享平台处理中/成功等模板。
- 支持延迟、超时、连接重置、限流、错误码等故障注入。
- 支持变量：请求字段、请求头、时间、UUID、流程实例变量。

### 5.4 状态机与回调

**优先级：P0**

- 支持 INIT、PROCESSING、SUCCESS、FAILED、REJECTED、TIMEOUT、CANCELLED 状态。
- 支持按查询次数、时间或请求字段推进状态。
- 支持回调延迟、重试、重复、乱序和签名。
- 支持按业务单号查看、人工推进、重置和清理流程实例。
- 流程实例必须具备 TTL，避免测试数据无限积累。

### 5.5 调用记录与回放

**优先级：P1**

- 记录请求摘要、匹配场景、响应摘要、耗时、错误和 TraceId。
- 支持按业务单号、TraceId、服务、接口、场景查询。
- 支持敏感字段脱敏和记录 TTL。
- 支持历史请求回放到指定场景和环境。
- 支持导出测试报告。

### 5.6 AI Agent 能力

**优先级：P1/P2**

- 从第三方文档、OpenAPI、Java 接口和历史报文中生成接口契约草稿。
- 根据契约生成成功、失败、处理中、超时和回调场景草稿。
- 根据自然语言生成多步骤测试流程。
- 分析未匹配请求和真实/Mock 响应差异，给出原因建议。
- 检测第三方响应字段、错误码和签名规则变化。
- AI 只能生成草稿或建议，发布和生产变更必须人工审批。
- Agent 只能调用白名单工具，不允许直接执行任意代码或访问任意网络。

### 5.7 权限、发布与审计

**优先级：P0**

- 复用巡天统一认证和 RBAC。
- 场景、契约、配置和发布操作全部审计。
- 支持草稿、测试、审批、发布、回滚生命周期。
- 生产环境默认禁止访问 Mock 服务。
- 支持双人复核或审批策略。

## 6. 非功能需求

- 可用性：测试环境 Mock 服务可用性不低于 99.9%。
- 性能：无故意延迟时 Mock P95 小于 50ms。
- 扩展性：运行节点无状态，可水平扩展。
- 安全性：请求/响应脱敏；真实上游地址白名单；禁止 SSRF 和任意脚本执行。
- 可观测性：提供请求量、命中率、未匹配率、P95、回调成功率、重试次数和真实/Mock 流量占比。
- 可恢复性：配置和场景版本可回滚；流程实例可清理和重放。

## 7. 典型业务流程

### 7.1 开发接入流程

引入 SDK → 在第三方客户端方法添加注解 → 配置 provider/api → 配置中心开启 MOCK → 业务代码正常调用。

### 7.2 场景发布流程

注册接口 → 创建场景 → 契约校验 → 测试执行 → 审批 → 发布到环境 → 观察指标 → 必要时回滚。

### 7.3 AI 辅助流程

上传第三方文档或导入历史报文 → Agent 生成契约和场景草稿 → 自动校验 → 人工确认 → 发布场景。

## 8. MVP 范围

- 独立 Mock 服务。
- SDK 注解、配置动态切换、Feign/RestTemplate 适配。
- OA、e 签宝、共享平台各 3 个核心接口。
- 固定/模板响应、状态机、回调、延迟和失败注入。
- 服务、接口、场景、发布、回滚、调用记录和审计。
- AI 先实现契约解析和场景草稿生成，不实现自主发布。

## 9. 验收标准

1. 业务服务仅增加 SDK 依赖、一个注解和配置，即可切换 REAL/MOCK，切换无需重启。
2. 三类第三方至少覆盖成功、失败/驳回、处理中、超时和回调重试场景。
3. 同一业务单号的查询和回调状态可重复复现，测试数据可清理。
4. 调用记录可按 TraceId 和业务单号定位，敏感字段已脱敏。
5. 场景发布、回滚、开关和 AI 生成内容均有审计记录。
6. Mock 服务不可用时，系统按配置执行快速失败或明确回退策略，不得静默访问真实生产接口。

## 10. 版本规划

- V1.0：SDK、核心 Mock、场景管理、状态机、回调、审计。
- V1.1：回放、契约校验、Forest/WebClient 适配、故障注入增强。
- V1.2：AI 契约解析、场景生成、测试流程生成、差异诊断。
- V2.0：MQ/文件协议、流量录制生成、智能覆盖率和漂移治理。
